Visma · internal plugin for Claude Code

Closing the Loop

One plugin that takes a feature the whole way: customer signal → validated prototype (built from your team's own components) → engineering handover → reviewed, shipped code. One source of truth, no copy-paste between tools — and nobody has to learn skill names.

①Discover & prototype

For PMs & designers. Customer data → scored opportunity → PRD → clickable prototype made of your product's real components → usability test plan.

②Hand over

The PM→engineering seam. One ticket carries everything; the handover grounds it in the live codebase — with or without an approval gate, your team's choice.

③Build & ship

For developers. “Take KEY to a PR” — plan, implement, test, review, release, and feed the learnings back. That's the loop closing.

00

Before you start

You need

  • 🔑 A paid Claude subscription (Pro/Team/Enterprise) with Claude Code — the desktop app's Code tab or the claude terminal.
  • 🧾 A tracker connector for your team's Jira or Linear — needed from the moment you publish a ticket. Discovery alone needs none: /plugin install linear@claude-plugins-official (or atlassian@…), then authorize once.
  • 🎨 Figma connector — optional. Adds design-vs-code checks and visual prototype verification. Everything runs without it.
  • 💻 For developers: a checkout of the target repo and an authenticated gh CLI.

⚠️ Already have the Discovery to Prototype Engine plugin?

Uninstall it first (/plugin → uninstall). Closing the Loop contains everything it had, upgraded. If both stay installed, the same phrase can silently trigger the old skill instead of the new one — this has actually happened in a pilot, and it's confusing to debug. One phrase, one skill.

01

Download & install

Visma's enterprise setup keeps plugins invisible across companies, so this plugin is distributed as a zip — same pattern as the Discovery Engine.

⬇︎  Download closing-the-loop-plugin.zip
v0.2.0 · ~850 KB · checksum
  1. Unzip it somewhere permanent — e.g. your home folder. You'll get a closing-the-loop/ folder. Don't delete it after installing; the install points at it.
  2. Open a terminal, start Claude Code by typing claude, then run these two commands inside it:
/plugin marketplace add ~/closing-the-loop
/plugin install closing-the-loop@closing-the-loop
  1. Verify: run /plugin — you should see closing-the-loop listed and enabled, with 74 skills. That's it — installed once, available in every project and in the desktop app too.

Updating later: download the new zip, replace the folder's contents, then /plugin marketplace update closing-the-loop + reinstall.

02

Start using it

Say three words:

start CTL

The front door checks what you have (connectors, config, your codebase), shows you the journey, and asks one question: start from the beginning, jump to a specific point, or fix what's missing? From there, everything is guided — every step ends with a checkpoint and a clear next move. No skill names to memorize, ever.

The journey one feature travels

DISCOVER Stages 0–3 Customer data → opportunities → scored choice → PRD
PROTOTYPE Stages 4–5 Scan YOUR components → clickable prototype from them
VALIDATE Stage 6 Experiment plan + usability test
PUBLISH — One tracker ticket; its key is the handoff
HAND OVER Stage 7 Delivery Context (or governed Brief + sign-off)
BUILD — “Take <KEY> to a PR”
SHIP — Release, measure, feed learnings back

The prototype is real framework code importing your team's actual components — so engineering converts working code into the feature, not a picture. Anything the prototype couldn't use gets flagged honestly, with a fix-list.

Help & support

The plugin doesn't show up after install

Run /plugin in a fresh session. If the marketplace add failed, check the path points at the unzipped closing-the-loop folder (the one containing skills/). In the desktop app, plugins installed via terminal appear after a restart.

A skill behaves like an older version

You probably still have the standalone Discovery Engine plugin (or personal copies of its skills) installed — see step 00. Uninstall it; Closing the Loop supersedes it.

Setup says it can't see my Jira/Linear

The connector isn't attached to this surface. Install it where you work (terminal: /plugin install linear@claude-plugins-official; desktop app: Settings → Connectors) and authorize it once.

Something went wrong mid-stage / I want to re-run one stage

Every stage saves its output as a file, so nothing is lost. Say continue from stage N, or jump: I already have a PRD. Type / to see every skill and run one directly.

Feedback — anytime, 30 seconds, anonymous

In any session, say give feedback — a 1–5 rating plus an optional comment. You don't need to finish anything first. It genuinely steers what we improve next.

Privacy & telemetry: the plugin sends anonymous usage events (skill name, stage id, a hashed machine id — never prompts, file contents, ticket keys, names, or emails) so we can see adoption and where people get stuck. Opt out anytime with export CLOSING_THE_LOOP_TELEMETRY_DISABLED=1. This page counts views and downloads the same anonymous way.
